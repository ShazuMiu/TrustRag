TrustRAG v2: retrieval you can check, answers you can cite

A redesigned RAG pipeline that retrieves better evidence, refuses to answer from thin air, and checks every sentence's citation before showing it. It is built from your literature analysis (the 23-paper systematic review and the CSE 400 report) and fixes the specific weaknesses in the current TrustRAG code.

01Summary

Three goals, each tackled by more than one stage of the pipeline, because the review's main finding is that no single technique solves citation reliability (RQ6, RQ7).

Retrieval

Hybrid BM25 + dense search fused with Reciprocal Rank Fusion, a cross-encoder reranker, and a CRAG-style quality gate with corrective fallback and an entity-coverage check.

Less hallucination

A citation-enforced prompt with an explicit abstain token. Sentence-window NLI verification with a numeric/identifier guard. Unsupported claims are rewritten from evidence or removed, and the system abstains when evidence is missing.

Correct citations

Each claim is checked against the source it actually cites. Ghost citations are deleted, misattributed claims are re-cited to the passage that entails them, and unnecessary citations are pruned (CiteFix / VeriCite style).

04Stage by stage: what each part does, and why

Each design choice is tied to a finding from your review or report, and to the file that implements it.

1 · Ingestion and chunking trustrag/ingest/

Loads .md/.txt (with optional front matter for title/year/url), .pdf (PyMuPDF or pypdf), .docx and .jsonl. The chunker groups whole sentences up to about 120 words with a one-sentence overlap and assigns stable IDs like padma_bridge::c0. Chunks never split a sentence, because a claim whose evidence is cut across two chunks is a common source of "silent" citation failures (review, error type 5).

2 · Hybrid retrieval trustrag/retrieval/hybrid.py

BM25 finds exact names, numbers and rare terms. Dense embeddings (BGE in full mode) find paraphrases. Their ranked lists are merged with Reciprocal Rank Fusion: score(d) = Σ 1/(60 + rank). RRF needs no score normalization and is robust when either retriever fails. This implements the "hybrid lexical-semantic matching" from your report (§2.1.10) and the sparse + dense combination in the review (RQ3).

3 · Reranking trustrag/retrieval/reranker.py

A cross-encoder (BAAI/bge-reranker-base) reads the query and passage together and outputs a relevance probability. That probability reorders the candidates and also feeds the gate. In lite mode, an IDF-weighted query-coverage + cosine + bigram score stands in.

4 · Retrieval gate and corrective fallback trustrag/retrieval/gate.py

Inspired by CRAG. If the best relevance ≥ upper, the evidence is correct. Below lower it is incorrect; in between it is ambiguous. For ambiguous or incorrect evidence, the gate rewrites the query (with the LLM, or by pseudo-relevance feedback offline), widens the pool, optionally searches Semantic Scholar or DuckDuckGo, and reranks against the original question. If the evidence is still incorrect, the system abstains rather than letting the LLM answer from parametric memory, which is the root cause of post-hoc rationalized citations (review: up to 57%).

Entity-coverage check (new). Names, acronyms and numbers in the question must appear in the retrieved passages. Multi-word names must appear close together. "How long is the Jamuna Bridge?" retrieves passages about the Padma Bridge and the Jamuna river, but no passage mentions "Jamuna … Bridge", so the gate refuses instead of answering about the wrong bridge. This check costs no model calls.

5 · Citation-enforced generation trustrag/generation/

The prompt numbers the sources [S1]…[Sk] and requires a citation at the end of every sentence. It forbids citing unlisted labels and outside knowledge, and offers the exact token INSUFFICIENT_EVIDENCE as a legitimate way out ("active grounding" in the review). Temperature is 0. One HTTP client speaks the OpenAI chat protocol, so Groq, OpenAI, Gemini, Ollama, LM Studio and vLLM all work by changing two config lines.

6 · Claim extraction trustrag/verification/claims.py

Splits the answer into sentence-level claims (the ALCE unit) and parses [S1], [1], [S1, S3] and [S1][S2]. Citations placed after the full stop are re-attached to the right sentence. Labels that don't exist in the context are flagged as ghost citations (fabricated attribution, error type 1).

7 · NLI verification trustrag/verification/verifier.py

For each claim and each passage, the claim is tested against every 1-, 2- and 3-sentence window. Each claim gets one of four verdicts:

VerdictRuleError type it catches
supporteda cited passage entails the claim (or the cited windows do jointly)none
misattributedthe cited passages don't entail it, but another retrieved passage doesevidence mismatch / wrong citation / ghost citation
contradictedcontradiction ≥ τc, or the wording matches but a number or code differscontradictory generation / numeric distortion
unsupportednothing retrieved entails ithallucination / post-hoc rationalization

Numeric & identifier guard. Every number (8,611, 6.15, 2022) and alphanumeric code (BM25, K2, T5) in the claim must literally appear in the evidence window. NLI models are known to miss small numeric perturbations (review, NLI limitations), and this rule catches them for free.

8 · Correction trustrag/verification/corrector.py

  • Ghost citation → removed, and the claim is re-cited if a passage supports it.
  • Supported but over-cited → citations that add no support are pruned, which raises citation precision.
  • Misattributed → re-cited to the passage(s) that entail it (up to 2), the CiteFix idea with NLI instead of similarity.
  • Unsupported / contradicted → the LLM rewrites the sentence using only the top-2 evidence passages, and the rewrite is re-verified (VeriCite-style). If it still fails, or no generative LLM is available, the sentence is removed.

9 · Answer policy corrector.apply_policy

HALT-RAG style. No surviving claims → abstained. Fewer than 50% surviving → partial, with a visible note. Otherwise → answered. A confidence score = mean entailment of kept claims × kept ratio.

10 · Logging, evaluation, interfaces logging_db.py · evaluation/ · app/

Every run is stored in SQLite (query, answer, verdicts, timings). The evaluation harness compares systems, runs ablations and fault injection, and writes a self-contained HTML report. A Flask server provides a REST API and a web UI where citations are clickable and each claim's verdict is visible.

The ablations isolate each component's job. Removing correction brings back every hallucination and citation error. Removing the gate keeps citations clean but lets unanswerable questions through (12.5% refused instead of 62.5%).

Why TrustRAG scores a "perfect" 1.000 hereIn this run, the judge is the same lexical NLI that the verifier uses, so TrustRAG is partly grading its own work, which is the circularity problem your review describes (RQ7). The ablation pattern is meaningful; the absolute 1.000 is not. In full mode, the judge is a different DeBERTa model, and you should expect lower numbers.

C · Retrieval and real-extractive run

With the extractive stand-in (which never hallucinates), every system scores 1.0 on grounding. The difference shows in abstention: 12.5% → 62.5% correct refusals, with 0 false refusals. On the small demo corpus, all retrievers reach Recall@5 = 1.0 (BM25 Recall@1 0.964, hybrid 0.988), so retrieval differences must be measured on the larger pooled corpora below. Mean overhead of verification + correction: about 10 ms per question in lite mode. With DeBERTa on CPU, expect roughly 0.3–1.5 s, comparable to HALT-RAG's reported +0.9 s.

copy .env.example .env          # (Linux: cp) then put your NEW key: GROQ_API_KEY=gsk_...

14Limitations and next steps

  • Not yet measured in full mode. All numbers in this guide are from lite mode or a simulated LLM. Run E1–E5 before claiming improvements in the thesis.
  • Correctness ≠ faithfulness. NLI shows that a passage supports a claim, not that the model used it (review RQ7). Mechanistic probing (FACTUM) needs white-box access.
  • Entity check can over-refuse when the question uses a different name than the documents (e.g. "USA" vs "United States"). Turn it off with retrieval_gate.entity_check: false, or add aliases to your corpus.
  • Gate thresholds are model-specific. Tune upper/lower on 30–50 dev questions whenever you change the reranker.
  • Sentence-level claims. A long sentence with two facts is one claim. LLM-based atomic decomposition is an easy extension inside claims.py.
  • Lexical NLI (lite) is weak on negation and paraphrase. It exists only for offline testing; use DeBERTa for results.
